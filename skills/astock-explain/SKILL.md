# 股票术语讲解与图解规范（小白友好）

## 小白判定（满足其一即按小白对待）

1. 画像（面板「个性化设置」）术语档 = **「解释术语」**——对话里通常带着
   「专业术语首次出现时用一句大白话解释」的用户要求（画像前缀注入的信号）；
2. 用户自述新手/小白，或提问方式明显是入门级（如「什么是 K 线」「跌停了是不是钱没了」）。

画像术语档为「不解释」时本技能基本不触发，用户点名要图再照做；两档都没线索时
正常回答即可，不主动推销图解。

## 回答流程（先答后图，两步走）

1. **第一步必须先把问题答完**：大白话 + 结论先行，配一个生活化比喻
   （如「PE 就是按现在的赚钱速度，几年回本」）。这一步要独立成立——
   用户不看图也能懂；绝不能甩一句「看图吧」代替回答。
2. **第二步按术语难度动态决策，不要每词必问**：
   - **难懂**（要看过程/变化/对比才能懂的：除权除息、复权、换手率、量价关系、
     做空、杠杆、K 线形态、回撤与最大回撤、网格/定投摊成本……）：
     **直接生成图解，不等用户确认**——对小白来说「要不要图」本身就是额外负担；
   - **一般**（一两句话能说清的：涨停、一手、印花税……）：答完加一句引导话术
     （「需要的话我可以把这个概念做成能动手玩的互动图，要吗？」），用户点头再做；
   - 拿不准按「一般」处理。同一会话同一术语只生成一次，刚生成过的不要重复生成。

## 生成方式（先查本地技能，再自己造；产出一律内嵌预览）

1. 生成前**先看当前可用的技能清单**：凡是能产出可交互 HTML / 图表 / 动画 /
   教学页面的技能（html、html-diagram、animate、artifacts-builder、prototype
   这一类，名字以实际清单为准），**直接用，不要自己重造**。
2. 清单里没有合适的：自己写**单文件** HTML——内联 CSS/JS，Canvas/SVG + 原生
   JS，零外部依赖、零网络请求、不用 CDN。写完**调用 `astock_show_html` 工具**
   （参数 `title` + `html` 全文）：图解会直接内嵌在对话消息里可交互预览，工具
   同时落盘 `~/.dsh/astock-workbench/explainers/` 存档。**绝不要**让用户自己去
   文件管理器或系统浏览器打开文件。
3. 体量纪律：一个概念一页，HTML 全文 ≤ 60KB（约 300 行，超限工具会拒收）；
   调用后用一两句话引导用户怎么玩、看什么变化——交互说法自由发挥，别每次都是
   「拖滑杆」，不要复述页面全部内容。

## 图解质量纪律

1. **一页一概念**：不做成术语大杂烩；页面顶部放一句结论式标题
   （如「市盈率 = 按现在的赚钱速度几年回本」）。
2. **必须可动手**：至少一处交互（滑杆、按钮、拖动、切换、输入……按概念自由设计），
   让用户改变量看结果（拖「每年盈利」看 PE 怎么变、点「除权」看股价和股数各变成多少）。
3. **动画只用来展示过程**（除权前后、成本怎么被摊薄），不做纯装饰动画。
4. **窄屏可用**：手机上不横向滚动（用户可能在手机上看面板）。
5. 对比类概念优先配持仓或示例数字，让结论直接写在图上
   （「股价便宜 ≠ 便宜」，配 PE 对比一眼看懂）。

## 数字纪律（与 astock-briefing 同源）

1. 图里若用用户真实持仓/行情数字，必须来自 astock_* 工具返回，禁止编造或心算；
2. 教学示例优先用明显是编的整数（「股价 10 元、每年赚 1 元」），并在页面上
   标注「示例数字，非真实行情」；HTML 是静态文件，真实数字会过期，能不用就不用。
