# 持仓截图对账规范

## 触发

用户发持仓页截图（券商App的持仓列表），或粘贴持仓表格文字，说「同步持仓 / 对账 / 按这个更新持仓」等。

## 流程（必须两段式，缺一不可）

1. **读图**：逐行提取「代码、名称、股数（持仓数量）、每股成本」。
   - 数字必须一位一位照抄截图原文，禁止估算、换算、四舍五入或心算；
   - 看不清或被遮挡的行宁可跳过并向用户说明，不要猜；
   - ETF/基金也要提取（5/1 开头的代码同样有效）；
   - 一次把全部行放进 `astock_reconcile` 的 `rows`，不要分批。
2. **预览**：把工具返回的差异表**原样转述**给用户（新增/更新/一致/截图未出现，含旧值 → 新值），
   等用户明确确认（如「确认」「按这个更新」）。未确认前绝不带 token 调用。
3. **写入**：用户确认后，带预览返回的 `token` **原样**再次调用 `astock_reconcile`（rows 保持不变）。
   仅当用户明确表示「截图里没有的就是清仓了」，才加 `removeMissing: true`；否则不传（默认保留，防截图不全误删）。
4. 写入后调用 `astock_positions` 刷新工作台，并向用户报告写入结果。

## 卖出流水（自动补记，报告时要说）

写入时若存在清仓（removeMissing）或减仓（股数变少），工具会自动在卖出流水（trades.csv）补记一笔，
并在写入结果里逐笔列出「已实现盈亏」。向用户报告时把这几行一并转述——这是用户核对卖出记账的唯一入口。
口径提醒（用户问到再说，不用主动展开）：卖出价是当时行情快照（不是真实成交价）、成本是本地摊薄口径；
用户给出实际成交价时，用 `astock_record_trade` 补录更正或让其直接改 trades.csv。

## 纪律

1. 截图里的「总资产/可用资金/持仓盈亏」等汇总数字**不走本工具**：总资产用 `astock_set_total_assets`，
   现金用 `astock_set_cash`，且都要用户点头才写。
2. token 是防串写凭证：只能原样传递，不能自己构造、截断或修改；rows 在预览和写入之间一个字都不能变。
3. 差异表里的「旧值 → 新值」仅供用户核对，不要自行调和或替用户判断哪边对。
4. 工具报错（校验失败/token 不匹配）时如实转述，引导用户重新截图或重新确认，不要换个参数绕过。
5. 已自动补记过的卖出不要再用 `astock_record_trade` 重复录同一笔——流水是审计轨迹，重复会虚增已实现盈亏。
